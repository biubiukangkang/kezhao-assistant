## 2026-09-21 javac GBK 解码中文注释 →「程序包不存在」假错误（本次最大坑）

**现象**：新增 `GalleryStorePlugin.java`（含中文 javadoc/字符串，UTF-8）后 gradle 编译报「程序包 com.getcapacitor.annotation 不存在 / 找不到符号 @CapacitorPlugin」。但同 jar 里 `com.getcapacitor.Plugin` 等核心类全部正常，`javap` 能读出注解类，官方 Kotlin 插件同样 import 编译无恙。

**排查路径**（半天才闭环）：清构建缓存 ✗、删疑似增量编译状态 ✗、ASCII 路径对照 ✗、手工解 jar 对目录编译 ✗、二分删行 → **删掉 javadoc 块或删掉相邻 import 行都能"好"**——行位移敏感 + 内容敏感的诡异组合。

**根因**：Windows javac 默认按平台编码（GBK）解码源文件。UTF-8 中文注释的多字节序列被 GBK 按 2 字节组队时，特定字节恰好吞掉后续换行/关键 token，导致 import 解析错乱——报出来的却是不相干的「包不存在」。加 `-encoding UTF-8` 手工编译仍复现，说明该 jdk 21.0.12 下解码器行为还有更深的问题，未究。

**修法（双保险，已固化）**：① 安卓侧 .java 源文件**一律 ASCII-only**（中文走 `\uXXXX` 转义，GalleryStorePlugin 里的「课照助手」就是 `\u8bfe\u7167\u52a9\u624b`）；② `app/build.gradle` 给 JavaCompile 统一 `options.encoding = 'UTF-8'`。

**教训**：排这类「包不存在但 jar 里明明有」的错，先看报错类所在源文件有没有非 ASCII 内容，别急着怀疑依赖和增量编译。排查时 javac 输出是 GBK，`grep 中文` 匹配不上会假阴性——先 `iconv -f GBK` 再 grep。

## 2026-09-19 QMuse 平台迁移校验的两个拦截

**现象**：`qmuse import` 失败：
1. `Existing TanStack root layout contains unsupported providers or UI: @/components/ui/sonner:Toaster`——根布局（__root.tsx）不允许挂全局 provider/Toaster。
2. `Conflicting configuration paths: "/", "/"`——平台打包器把 `_app.tsx` + `_app/index.tsx` 结构解析出两个 "/" 路由（本地 tsr generate 无冲突，服务端必炸）。`--force` 也救不了。

**解法（已固化进代码结构）**：Toaster 下沉到 PageShell / camera / course-album 各页面；routes 目录完全平铺（不用 pathless layout 目录），Tab 页共用壳组件 page-shell.tsx。
**注意**：平台上的"发布"动作在 QMuse 网页端（CLI 只到导入生成版本+发布产物），需账号登录网页操作。

## 2026-09-19 Vite dev server 在 Windows 卡旧代码

**现象**：改完代码 `curl 模块 URL` 返回的仍是旧 transform 结果，日志无 HMR 记录；重启 `npm run dev` 报"Port 5173 is already in use"——TaskStop 只杀了 npm 外壳，node/vite 子进程（PID 在 `netstat -ano | grep :5173`）残留。已通过 vite.config.ts 开 `server.watch.usePolling` 根治大部分场景，但个别文件仍可能漏，重启是兜底。

## 2026-09-20 QMuse 云服务接入三连坑

**1. 产物校验器 Windows 误报**：`validate_appwrite_artifacts.mjs` 用 `path.relative()` 得到 `src\services\appwrite.ts`（反斜杠），与规则里的 `src/services/appwrite.ts`（正斜杠）永不相等，导致 appwrite.ts 自身被当业务代码扫描，报出"SDK 只能在 appwrite.ts 创建 / 必须通过 executeQmuseFunction / 不得直接导入 appwrite"三条假错误。平台侧质量门无此问题（Linux），本地这三条可忽略；真错误（schema/scopes/SDK 版本）要修。

**2. qmuse dev 的 origin 校验**：启动后只认 `http://127.0.0.1:5173/`，用 `localhost` 访问直接返回 `{"success":false,"message":"Invalid local development origin"}`。banner 里打的 Local 地址就是准的。

**3. import 的版本覆盖确认**：上次在网页端"发布"会推进平台版本号，之后再 import 会报"平台版本已从 X 更新为 Y，请同步最新源码"。确认本地源码是最新（git 干净）后 `qmuse import . --force` 覆盖；首接云服务还要 `--cloud-mode QMUSE --confirm-cloud-service`。

## 2026-09-20 教务系统探测首轮实测暴露的五个坑

用户实测"识别不出来"后本地驱动云函数代码逐站复现，根因与修法：

1. **无协议输入直接拒**：用户自然输入 `jw.xxx.edu.cn`，此前按无效地址报错。修法：https 优先、http 兜底自动补协议。
2. **根路径 404 ≠ 连不上**：有的学校教务必须带 `/jwglxt/` 路径（如浙财），此前根 404 就报"连不上"，走不到子路径。修法：探测层合并协议回退与子路径并发探测（/jwglxt/、/jwglxt/xtgl/login_slogin.html、/jwxt/、/jsxsd/）。
3. **新版正方（jwglxt）完全没适配**：这是当前高校主流装机版。登录链路：GET `xtgl/login_getPublicKey.html` 拿 RSA 公钥（base64 modulus/exponent）→ 手拼 PKCS#1 DER + `crypto.publicEncrypt` 加密密码 → POST `xtgl/login_slogin.html`（yhm/mm/yzm + csrftoken）；验证码在 `/jwglxt/kaptcha`（js 动态设 src，HTML 里抓不到）；课表是 JSON 接口 `kbcx/xskbcx_cxXsKb.html?gnmkdm=N2151`。
4. **系统识别被门户页误触发**：页面里出现 "jwglxt" 字样（导航链接）就判成新版正方。修法：判定特征收紧到登录表单本身（name="yhm"、login_slogin、checkcode.aspx）。
5. **老正方 cookieless 会话**：ASP.NET 无 cookie 会话把会话 ID 放 URL 括号段（`/(xxxisbn)/default2.aspx`），靠 cookie 维持会话必挂。修法：探测返回最终 pageUrl，登录/课表 URL 全部相对它解析。

调试利器：写一个 mock req/res 的 node 驱动脚本直接 import 云函数 src/main.js，本地就能复现全部探测行为（云函数是纯 Node 无平台依赖），比部署到云上试快一个量级。

## 2026-09-20 线上鼠标滚轮失效（iframe 嵌入 + body 滚动）

**现象**：宸哥电脑浏览器测线上版，所有页面滚轮滚不动；手机端一直正常。本地排查无静态滚动锁、无遮挡层、无元素抖动，编程滚动（scrollTo）正常。

**根因**：QMuse 线上页面是平台外壳嵌 iframe 承载应用，应用此前依赖 body 自然滚动；iframe 高度随内容自适应后内部文档无滚动空间，鼠标滚轮事件不会跨 iframe 传给外层页面。触摸滚动路径不同，所以移动端从未暴露。

**解法**：布局改为应用内部滚动容器（外壳 `h-dvh flex flex-col`，内容区 `overflow-y-auto`，BottomNav 从 fixed 改 flex 尾部；PageShell 与相册页两处）。滚动发生在应用自己的容器，不依赖宿主环境。**新增页面一律用 PageShell，别回退到 body 滚动 + fixed 导航。**

**排查教训**：IAB 自动化的 Playwright click / cua.scroll 在此环境有已知超时缺陷（见 2026-09-19 条），排查鼠标类问题时先区分"应用 bug"和"自动化工具缺陷"，功能层用 evaluate 原生驱动验证。

## 2026-09-22 状态栏适配三连坑（每个方案都在模拟器"通过"过）

1. CSS `env(safe-area-inset-top)` 在安卓 WebView **恒为 0**（状态栏不算 display cutout）——v1.4 首版方案无效。
2. `@capacitor/status-bar` 的 `setOverlaysWebView(false)` 在 targetSdk 35+ 是**官方 no-op**——v1.4.1 方案在标准模拟器假通过（走了别的渲染路径），宸哥国产真机现形"标题和 8:41 叠在一起"。
3. `fitsSystemWindows(true)` 能分开但状态栏成孤立系统色块，页面标题下推——宸哥批"留是留了，毫无美观"。
**终解（v1.4.7）**：沉浸式——透明栏叠页面、insets listener 存高度、插件给 JS、**÷ devicePixelRatio**（物理像素直注=留白 3 倍高，宸哥精确定位"怀疑把物理像素当 CSS 像素用"）、页面 max(var,env) 留白。
**教训**：安卓 WebView 的 UI 适配，任何"标准方案"都必须模拟器+真机双实证；验收要带度量数字（标题距顶 px），"看起来好了"不算数。

## 2026-09-22 相册 picker 临时授权失效

选图返回的 File 是临时授权引用，**延迟读取**（用户选完图→看预览→再点"开始识别"）报 `The requested file could not be read`。修法：onChange 里**立即**读成 dataURL 存字符串，后续只用字符串。CDP 抓 toast 定位（adb forward webview_devtools_remote + node WebSocket Runtime.evaluate 抓 sonner 文本）。

## 2026-09-22 WebView fetch 公网资源被 CORS 拦

应用内"检查更新"第一版用 WebView fetch 拉 GitHub Release 的 version.json——资产域无 `Access-Control-Allow-Origin` 头，**任何网络环境下都静默失败**（catch 返回 null），上线两周没人发现（静默设计的代价）。修法：CapacitorHttp 原生请求免 CORS。**教训**：WebView 里凡跨域公网资源一律原生 HTTP；"静默失败"的功能要有至少一次端到端实证。

## 2026-09-23 UI 自动化在 WebView 失效的工具链替代

MCP android_ui_tap 对 Capacitor WebView 点击不生效（无障碍树只有容器）。可用替代：`adb shell input tap`（原生注入）+ `adb shell uiautomator dump`（能抓 WebView 无障碍文本和 bounds，中文文案 grep 定位坐标）。DOM 级检查/截图用 CDP：`adb forward tcp:9223 localabstract:webview_devtools_remote_<pid>` + node WebSocket `Runtime.evaluate`（抓 sonner toast、量 getBoundingClientRect、查 CSS 变量）。
