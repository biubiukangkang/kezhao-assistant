## 1. 架构总览

```
React 19 + Vite 7 + TanStack Router（文件式路由 + hash history）+ Tailwind 4 + shadcn/ui
数据层：IndexedDB（idb 封装），本地优先；照片入库前压缩到长边 2048
EXIF：exifr（拍摄时间优先，mtime 兜底）
课表导入：SheetJS（教务 .xls/.xlsx）+ 行式文本粘贴解析
云服务：QMuse 云服务已接入（appwrite.ts 基础设施 + school_portal 表预留），当前无业务消费方，留给截图 AI 导入等后续能力
部署：qmuse import .（平台自动构建生成版本，发布动作在 QMuse 网页端）
```

## 2. 数据模型（IndexedDB：kezhaodb v1）

```ts
Course  { id, name, color, teacher?, createdAt }
ScheduleSlot {
  id, courseId, weekday(1-7), startMin, endMin,
  weeks?: number[],        // 任意周次组合（新数据，优先使用）
  weekStart, weekEnd,      // 旧字段，新数据保存时双写 min/max
  oddEven: "all"|"odd"|"even"  // 旧字段，按 weeks 推导
}
Photo {
  id, courseId|null(待分类), capturedAt, capturedSource("camera"|"exif"|"mtime"|"manual"),
  storageKey, matchMethod("auto"|"manual"|"ai"|"unmatched"), batchId, starred,
  note?,                   // 用户备注（QQ 空间式显示在照片上方）
  sourceKey?,              // 去重键 `${size}-${解析后时间}`
  deletedAt?,              // 删除时间；存在 = 回收站中，30 天后惰性清理
  blob, createdAt
}
AppSettings { semesterStart("YYYY-MM-DD"周一), periods: Period[](节次可增删) }
meta 表：settings KV + photoFolder(同步文件夹句柄) + backupReminder(备份提醒基线)
```

规则：读周次一律走 `weeksOf(slot)`（weeks 优先、旧字段回退），展示走 `slotWeekLabel(slot)`（"1-16周"/"单周"/"1-3,5-7周"）。删除课程时照片回待分类（courseId=null、matchMethod=unmatched），不丢照片。

## 3. 归档匹配算法（lib/match.ts，纯函数）

照片时间 → (星期, 当天分钟, 学期周次)，学期周次由 `semesterStart` 锚点算出（1-30 周外不匹配）。
先严格匹配（时段内），未中放宽 ±15 分钟（刚上课/刚下课），多命中取开始时间最近者；仍无 → 待分类。
时间来源：camera=拍摄时刻；导入=EXIF DateTimeOriginal/CreateDate 优先、mtime 兜底；用户可在查看器手动修正（source 变 manual）。

## 4. 存储、压缩与备份

- **压缩入库**（lib/archive.ts `compressImage`）：所有照片入库前长边压到 2048、JPEG 0.9（createImageBitmap 按 EXIF 转正，解码失败原样保存）。约降 90% 体积。
- **去重**：sourceKey = `${file.size}-${解析后拍摄时间}`，重复导入跳过。
- **回收站**：删除为软删除（Photo.deletedAt 标记），设置页回收站可恢复/彻底删除/清空，30 天超期由首页加载时惰性清理（purgeExpiredPhotos）。listPhotos 默认排除已删，备份（listAllPhotos）含回收站。
- **照片出口**（lib/photo-export.ts）：查看器单张「保存或分享」、相册页批量导出——Web Share API 可用（手机）调起系统分享面板（10 张一批），桌面逐张 a[download] 兜底。
- **备份提醒**：新增照片满 30 张且距上次提醒超 24h，首页 toast 提醒导出；导出成功后重置基线（meta.backupReminder）。
- **恢复预览**：选择备份文件先 inspectBackup 解析展示（导出时间/课程/照片/星标/体积 + 当前库对比 + 覆盖警告），确认后才 importBackup 覆盖。
- **照片文件夹镜像**（lib/photo-folder.ts，File System Access API）：用户在设置里选一次文件夹，新照片自动写入真实 .jpg（文件名含日期/时间/课程名）；支持重新授权/全量同步/停止。仅 Chromium 系支持，不支持时 UI 降级说明。IndexedDB 始终是主存储，文件夹是单向镜像。
- **备份**（lib/backup.ts）：导出单 JSON（课表/课程/照片 base64 内嵌，含回收站）下载；恢复 = 覆盖式写回。

## 5. 课表导入（两条路）

1. **文件导入**（lib/timetable-xls.ts）：教务 .xls/.xlsx 矩阵课表（列=星期、行=第X大节、格子=名称/教师/断续周次/教室，一格多课自动切分），SheetJS 解析。
2. **文本粘贴**（lib/timetable-parse.ts）：每行一节课的文本（"高等数学 周一 1-2节 1-16周"），token 剥离法解析，失败行标红可剔除。
两条路都产出 ParsedRow → 预览（components/timetable-preview.tsx 共用）→ 确认后 `applyTimetable` 替换现有课表（同名课程照片归属保留，消失课程照片回待分类）。节次换算：小节号"3-4节"= 大节索引 1（每大节 2 小节）。

> **决策记录（2026-09-20）**：教务系统在线抓取方向已彻底移除（入口、portal 服务、fetch-timetable 云函数、自动登记）。第一性分析结论：各校教务系统异构长尾（六大家 × 登录/验证码/可达性各不相同）、可达性持续收紧（统一认证 + 校园网锁）、对抗性运维成本高、验证必须有真实账号，投入产出结构性不划算。正方系适配器代码曾验证到"登录表单被真实服务器接受"的程度后按决策删除。后续课表导入增强方向：课表截图 AI 结构化提取（无需账号、一次开发全量用户可用，PRD Roadmap 原有方向）。schema 中 school_portal 表因平台 append-only 演进规则不可移除声明，业务代码已无引用（云面板可手动清理）。

| 路由 | 文件 | 说明 |

壳组件 `components/page-shell.tsx`：内容容器 + BottomNav + Toaster（Tab 页共用；全屏页相机/相册不用壳）。滚动一律发生在应用内部容器（外壳 `h-dvh flex flex-col` + 内容区 `overflow-y-auto`，BottomNav 为 flex 尾部而非 fixed）——QMuse 线上页面为 iframe 嵌入，body 滚动会导致鼠标滚轮失效；相册页同款布局。

## 7. 平台约束（QMuse，违反会被迁移校验拦截）

- **根布局（__root.tsx）禁止挂全局 provider/Toaster 等组件**——Toaster 已下沉到 PageShell / camera / course-album。
- **routes 目录必须平铺，不要用 `_app.tsx` + `_app/` 目录结构**——平台打包器会解析出重复的 "/" 路由导致导入失败。
- 部署 = `npm run build` → `qmuse import .`；应用绑定在 `.qmuse/project.json`（勿动、勿复制）。
- **平台上的"发布"动作在 QMuse 网页端**（CLI 只到生成版本+发布产物），需账号在网页操作。

## 8. 开发环境注意事项

- vite.config.ts 已开 `server.watch.usePolling`（Windows 默认监听会丢事件吐旧代码）；改完代码若页面行为不对，先 curl 模块 URL 确认 server 是否吐新代码——**组件体在 `?tsr-split=component` 子模块**，路由主文件只有壳。
- 端口 5173 残留进程：`netstat -ano | grep :5173` 找 PID 后 `taskkill //F //PID`。
